## 1.1 一策略一文档（核心原则）

每个**具体策略用一个主文档**管理全生命周期：日内 PA 策略是一个文档，双均线策略是另一个文档。
主文档使用 `templates/strategy.md` 模板，包含策略逻辑、研究记录、回测快照、参数优化、
风险档案、组合跟踪、评审记录、修订记录等全部章节，**逐次就地更新，不按阶段拆分文档**。

大体量材料（图表、参数网格、多轮回测明细）放入 `assets/{S-XXX}/`，在主文档中相对引用。
```
10_strategies/
├── S-001_日内PA-突破.md          ← 日内 Price Action 策略的完整档案
├── S-002_双均线.md               ← 双均线策略的完整档案
└── ...
```

## 2. 策略生命周期与文档管理

```
想法(Idea) → 研究(Research) → 回测(Backtest) → 优化(Optimization)
   → 组合(Portfolio) → 决策(Decision) → （上线/否决/搁置 → 归档）
```

生命周期的**全部阶段在同一份策略主文档内推进**：文档头部 `status` 字段与
第 2 章"生命周期进度"表反映当前阶段；每跨入一个新阶段须经过团队评审
（见 01_playbook），评审结论回填主文档。

| 阶段 | 主文档对应章节 | 准出条件（进入下一阶段的门槛） |
|------|----------------|-------------------------------|
| 想法 | §1-3 概要与逻辑 | 逻辑自洽、有明确的市场假设 |
| 研究 | §4 研究记录 | 假设有数据初验、风险点已识别 |
| 回测 | §5 回测记录 | 样本内外均达标、交易成本建模合理 |
| 优化 | §6 参数与优化 | 参数敏感度平缓、无过拟合迹象 |
| 组合 | §7-8 风险与组合 | 相关性矩阵、风险预算、压力测试完成 |
| 决策 | §9-10 评审与待办 | 团队协商达成结论，记录反对意见 |

组合层面的整体方案（成员构成、资金分配、压力测试）在组合评审会议纪要
（`70_meetings/`）与决策日志（`60_decisions/`）中维护，各策略主文档的 §8
同步自身在组合中的状态。

## 3. 协作方式

所有研究工作以**多角色智能体团队协商讨论**方式进行，角色定义、议事规则、
会议纪要格式见 `01_playbook.md`。每轮协商的结论落入 `70_meetings/`，
阶段性结论落入 `60_decisions/`。

## 4. 铁律（2026-10-12 用户修订，最高约束）

1. **活动范围仅限本目录**：团队只能维护 `strategy_research/` 之下的文档、方法库代码、策略代码（研究级）；**未经用户明确批准，不得修改 `strategy_research/` 以外的任何文档和代码**。
2. **正式运行需显式批准**：研究级策略代码仅用于回测/分析，**未经用户明确批准不得作为正式策略运行**（不得接入实盘/模拟盘）。
3. **转工程须用户批准**：团队协商推荐策略后，**结论由用户显式批准**，批准后才转工程团队实施；团队自身无权移交实施。
4. **文档先于结论**：没有落档的回测结果、参数、结论一律视为不存在。
5. **记录反对意见**：被否决的想法必须写明否决理由后归档，禁止无声丢弃。
6. **可复现**：回测与优化记录必须包含足够信息（数据范围、参数、成本假设）以便复现。

## 5. 研究级代码区

```
strategy_research/
├── code/
│   ├── methods/      # 方法库代码实现（MLIB 方法的 Python 实现，研究级）
│   ├── strategies/   # 策略代码（研究级原型，仅回测/分析用）
│   └── tests/        # 研究级代码的自测
```

- 研究级代码与工程代码物理隔离（本目录内），实现时可参考工程侧组件但**不修改工程代码**
- 研究级策略代码文件头必须标注：`# RESEARCH ONLY - 未获用户批准不得正式运行`
- 升级为正式策略的路径：团队推荐 → **用户显式批准** → 工程团队按移交单实施
