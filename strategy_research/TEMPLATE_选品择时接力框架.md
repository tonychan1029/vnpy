# 选品↔择时接力框架模板（固化 v1.0）

> **用户定调（2026-10-14，本模板的最高约束）**：
> ① 扫描策略与择时策略是**接力**关系：扫描选品，选出中周期上有机会的品种，
> 把（需要监控的小周期 + 可能出现通知用户人工监控买点的信号）交给择时策略；
> ② 选品层对**趋势、背景、回调**做量化；择时层**只对小周期出现的预警信号
> 做监控**；
> ③ 择时策略给出的预警信号，**由用户自己去监控入场信号、人工开单**；
> 未来若稳定，可升级程序化开单（现阶段冻结为只预警）；
> ④ **选品策略可以多种并行**，且会随研究产出**持续新增**——研究侧的目标
> 就是持续输出可工程化的选品策略，成熟一个、加一个 scanner；
> ⑤ **择时策略设计为一个策略**：对**所有**选品池的品种，按任务单指定的
> 监控周期与信号预期做监控并推送——不随选品策略增加而增加实例数量；
> ⑥ 两层都需持续优化，但**分工边界是冻结项**：阶段判定/信号武装在选品层，
> 触发监控/预警在择时层；预警→人工开单（程序化为未来演进项）；
> ⑦ **交易模式定位（2026-10-14 重申）**：不追求全自动量化——把当前的
> 人工交易模式先程序化为「智能选品 + 择时预警 + 人工下单」，**结合人的
> 入场能力提高胜率、效益最大化**；策略研究团队的持续工作输出为该模式
> 供血（工程化选品策略 + 择时优化 + 研究验证）。
> ⑧ **中国期货市场微结构特征（2026-10-15 固化，策略设计的基本盘）**：
> 庄家/机构极度贪婪，高度利用监管缺位获取暴利。技术分析表现：
> a) 大量大幅度高低开（隔夜外盘+情绪放大）；
> b) 频繁打损前低前高后迅速拉回（stop hunting——前低/前高是猎杀区非支撑区）；
> c) 突破后不回调单边走到位（突破即入场，不等回调）。
> **策略设计必须利用这些特征产生利润，而非用教科书假设对抗市场现实。**
>
> 本模板固化的是**输入/输出契约与职责边界**，不是任何具体策略的参数。

## 1. 分层与职责边界

| 层 | 职责 | 明确不做 |
|---|---|---|
| **选品层（扫描）** | 大/中周期视角：**趋势、背景、回调三量化**；输出"择时监控任务单"（品种+监控小周期+武装信号+关键位+有效期） | 不做小周期信号触发；不下单 |
| **择时层（引擎/策略）** | 按任务单订阅小周期行情；只对**武装信号**做小周期预警（信号K判定、状态流转、触发） | **不做阶段判断**（选品层专属）；发现任务单与盘面矛盾只上报不改单；不下单（现版本） |
| **执行层（用户）** | 监控预警→人工判断入场信号→人工开单 | — |
| 执行层（未来） | 程序化开单 | 触发条件：稳定运行证明 + 用户显式批准（走 HO），当前**冻结** |

## 2. 选品策略：输入/输出契约

### 2.1 输入
| 输入 | 说明 | as-of 纪律 |
|---|---|---|
| 行情数据 | 背景周期（1d/60m）+ 结构周期（60m）+ 触发周期（15m/5m，自 1m 合成） | 只用已完成 K 线 |
| 品种域 | universe（连续合约清单，可 all/可 list）；实例命名 `{scanner}_{symbol\|ALL}_{tf}` | 换月由工程解析映射 |
| 策略参数 | 各扫描器自有（lookback、MA 周期、RR 门槛、TTL 等） | 变更走 HO/评审 |

### 2.2 输出＝择时监控任务单（schema 固化；字段名以 PoolEntry 为准）
| 字段 | 含义 | 必选 |
|---|---|---|
| `pool_id` | `{symbol}:{direction}:{scanner}`——**多选品并行的池隔离键** | ✅ |
| `scanner` | 选品策略名（并行身份） | ✅ |
| `symbol` / `exchange` | 标的 | ✅ |
| `direction` | long / short | ✅ |
| `selection_timeframe` | 选品周期（任务单有效期按它计） | ✅ |
| `exec_timeframe` / `monitor_tf` | **交给择时层的监控小周期**（可由规则量化选择，如 atr_pct 阈值→15m/5m） | ✅ |
| `signal_categories` | **武装信号列表**（择时层只监控这些类别的小周期预警） | ✅ |
| `context_tag` / `reason_code` | 阶段标签与选由（审计/通知文案；启用矩阵键） | ✅ |
| `key_levels` | 关键位（support/resistance/摆动点） | ✅ |
| `entry_limit` / `rr_ratio` | 参考价与盈亏比（通知用，非指令） | ✅ |
| `valid_bars` / `expires_at` | **双时钟有效期**：任务单按选品周期根数倒计时（缺省 12 根）；条目另有墙钟过期 | ✅ |
| `trend_state` / `pullback` | 趋势态与回调区（证据字段） | 可选 |
| `per_direction` / `stage_evidence` / `armed_signals` 逐信号列表 | S-004 编排契约升级项（阶段→信号矩阵），**v1.1 演进待落地** | 演进项 |

### 2.3 三量化要求（用户 2026-10-15 权威定义，选品层合格线）

选品层要解决的四个问题：

| 量化维度 | 判据来源 | 说明 |
|---|---|---|
| **趋势形态** | 波段高低点（HH/HL→趋势，LH/LL→反向，无结构→区间/盘整） | 确认当前品种是交易区间还是趋势 |
| **背景（PA 心态）** | 价格行为学背景——市场心态判定（多头控盘/空头控盘/多空拉锯） | 确定当前市场环境适合哪类策略 |
| **回调位置** | 回调是否到了支撑位。支撑判断三法：①波段高低点 ②K线密集区 ③交易区间上下边界 | 回调到了支撑 → 值得关注 |
| **衰竭信号** | 三推楔形、W底、M顶、量价背离、抛售高潮 | 确认趋势是否延续或衰竭 |

**选品层解决了"趋势形态 + 回调是否到位"的问题，剩下的交给择时层做小周期入场信号量化。**

### 2.4 择时层入场信号类别（用户 2026-10-15 定义）

择时层在小周期上监控以下信号类别（选品层通过 signal_categories 指定监控哪些）：

| 信号 | 说明 |
|---|---|
| 带量小平台收线突破 | 小周期平台整理 → 放量收线突破 |
| H2L2 | 高2/低2——回调后第二次同向极值 |
| 垂线/倒垂线 | 长影线反转信号 |
| 反包K线 | 当前K线完全包住前一根（方向相反） |
| 近均十字星小K线 | 价格靠近均线时出现十字星/小K线 → 挂破均线限价 |

### 2.5 选品预警定位（用户 2026-10-15 两次定调）

| 规则 | 说明 |
|---|---|
| **选品预警 ≠ 入场信号** | 选品层的职责是**提前发现并通知**"有品种正在接近交易机会"，不是给出精确入场信号；精确入场时机的判断由**择时层**承担 |
| **预警提前量** | 价格进入**区间高度的 1/4 范围内**即触发选品（不等触达边界——给用户留人工准备入场的时间窗口） |
| **分工** | 选品层说"这个品种值得关注"→ 择时层说"入场信号确认了"→ 用户决定是否下单 |
| **择时层联动** | 选品预警触发后，择时层按任务单开始监控小周期信号——**任务单生效 ≠ 入场信号**；精确入场信号由择时层判定 |

### 2.4a 选品输出 = 有经验用户可直接行动的完整通知（用户 2026-10-15 补充）

> **有经验的用户在收到选品通知后，不需要等择时层确认——看到关键位和方向，自己就能挂单入场。**

| 选品通知要素 | 用户行动 |
|---|---|
| `direction`（long/short） | 确定做多还是做空 |
| `key_levels.support` / `key_levels.resistance` | 支撑/压力参考 → 用户自定挂单价 |
| `entry_limit` | 参考入场价（当前价或边界价） |
| `rr_ratio` | 粗筛质量门槛（≥1.6 才通知） |
| `context_tag` | 当前市场阶段（趋势/震荡），辅助人工判断 |
| 用户自定 | 止损位（对侧边界或摆动点）、仓位大小、持仓期 |

**这意味着选品层的输出质量标准 = 有经验交易者看到通知后能否独立完成入场决策**。关键位精度和方向正确性是核心指标——不是预测 20 日走势，而是给出**正确的交易区间边界和方向**。

### 2.5 RR 准入底线（用户 2026-10-15 定调）

| 规则 | 说明 |
|---|---|
| **RR ≥ 1.6** | 低于 1.6 不触发选品（区间中段入场最危险，正确入场应在边缘 1/3 以内） |
| 依据 | 区间交易的正确入场位置在上方或下方 1/3 以内，对应 RR 1:1.6~1:1.8 |
| 生产参数 | `pool_config.yaml` `market_min_rr: 1.0` → `1.6`（ENVIRONMENT R10 登记，随工程下批部署） |

## 3. 择时策略：输入/输出契约

### 3.1 输入
| 输入 | 说明 |
|---|---|
| 任务单 | 选品层产出（§2.2）：订阅标的 + 监控小周期 + signal_categories（启用矩阵键：`context_tag + signal_categories`）+ key_levels + 有效期 |
| 小周期行情 | tick→1m→监控周期合成（执行周期 K 由 1m 合成，不用 datafeed 原生） |
| 生命周期控制 | WARMING_UP（预热判据达标前不产出不倒计时）/ PAUSED；双时钟：任务单 `valid_bars`（选品周期）vs 预案 `expire_bars`（执行周期），严格区分 |

### 3.2 输出
| 输出 | 说明 |
|---|---|
| **结构化预警**（非指令） | 信号量化结果 + 挂单预案 + 全生命周期状态；通知必须回答三问：**当前在择时什么信号、要等什么信号入场、挂什么单入场** |
| 通知 payload | 已契约冻结（QUANT_HANDOFF）；分渠道（cloudwebhook/Hermes）双通道 |
| 审计三元组 | 人的原始需求 → 落库指令 → 产出报警（指令历史只增不删） |
| ~~开单指令~~ | **冻结**。预警→用户人工监控入场、人工开单；程序化开单为未来演进项（稳定性证明 + HO） |

## 4. 多选品并行规范

1. 每个选品策略独立 scanner 实现 + 独立池命名空间（`pool_id` 含 scanner 名），互不覆盖；
2. 实例 = 模型 × 决策周期 × 品种域，命名 `{scanner}_{symbol|ALL}_{tf}`；
3. 同一标的被多个策略同时选中（同池并发）→ **编排冲突裁决**归研究侧 S-004
   （现行数据驱动规则：同窗反向冲突突破优先/回调降权、同向合并——MTG006
   复验通过待签批）；工程侧不做隐式裁决；
4. 新增/下线一个选品策略 = 增/删一个 scanner 注册，**不改他人**（并行解耦）。

## 4a. 主力换月处理（v1.1 增补，设计详见 RS018）

| 环节 | 规则 |
|---|---|
| 选品解析 | **永远选主力**（三级 OI 判定保留）；每轮扫描**强制重检**已解析键（修复 resolved 粘性——换月后系统性停旧主力的框架级缺口） |
| 任务单存续 | 主力一致性检查（扫描节点节奏）；换月→默认 **`expire`**（任务单自然过期）；`switch` 仅占位（key_levels/entry_limit 绑旧合约尺度，自动切实质=重建任务） |
| 监控与预警 | 换月→ **`contract.rollover` 预警**（旧合约 `signal.*` 抑制，仅放行换月事件）；bar 级 RolloverDetector 兜底（盘中合约码切换→任务 PAUSED） |
| 执行 | 预警→**用户平旧仓（默认）**或按新一轮任务单在新主力重开；程序化移仓冻结至阶段 2 |
| RegimeSwitch（模板外） | 日内强平=无跨换月持仓，维持现状 + 补换月通知推送 |
