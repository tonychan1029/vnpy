# 策略研究方法论·数据清洗·数据管理·模板框架·AI 策略 —— 建议方案

> 定位：承接《独立评估报告》（EVAL-001）的五域改进方案。每一项建议都标注
> 【依据】→ 指向评估发现，【动作】→ 具体可执行步骤，【成本】→ 人日估算，
> 【优先级】→ P0/P1/P2。原则不变：不代客下单、不误杀好基准、先证后做、
> 单一事实来源、实施须独立评审 + 用户批准（治理红线）。

---

## 0. 总纲：一句话路线图

**先把"证据生产层"的地基修好（前视/成本/复权），再把"阶段判定"这个软肋换掉
（规则版 → ML 增强），最后让 AI 做"判据生成器 + 关键位评分器"而非"黑箱下单器"。**
三阶段：
- **阶段 A（地基，1–2 周）**：前视纪律 + 口径统一 + 复权/量能落地 + 死刑传导 + P0 代码 bug。
- **阶段 B（软肋，2–4 周）**：context_tag 重构（ML 版阶段分类器）+ S-004 契约三缺口 + 关键位/边界预注册验证。
- **阶段 C（AI 前沿，持续）**：AI 生成判据/因子/信号组合，走"生成→预注册验收→HO→影子→观察期"全链。

## 1. 策略研究方法论改进建议

### 1.1 🔴 根治前视污染（最高优先，旗舰证据已中招）
- 【依据】RS013 mom6×BREAKOUT IC +0.364 系前瞻 GT 标签前视污染，point-in-time 引擎标签
  复算仅 +0.029 未过（RS013 §4 局限0 + cand007_engine_tag.md）。RS012 自己设计了正确的
  操作性真值（as_of 前/后严格分离），但 RS013 消费 GT 时未守住 as_of 纪律；h2h 分桶也曾
  犯 0%/100% 循环论证（h2h_exhaustion.md:60-63）后自纠。
- 【动作】
  1. 立一条**硬规则**：任何"阶段/标签条件化"的统计量，条件必须用 **point-in-time（as_of
     可得）** 标签，禁止直接用 GT（前瞻实现）标签做条件；GT 只用于评估，不用于建模。
  2. 给 CAND-007 / mom6 建立**干净的 as_of 复算**（用生产 v1 标签 + 后复权 + 分块），
     复算前 CAND-007 回退"gated"状态，不得引用 +0.364。
  3. 每个分析脚本头登记"标签口径：GT / as_of / 引擎标签"三选一，混淆即判不合格。
- 【成本】0.5 人日立规 + 1 人日复算 CAND-007。
- 【优先级】P0。

### 1.2 🔴 收益口径 vs 可交易口径统一
- 【依据】全库仅 RS016 按 DEC003+1tick 跑（同一事件集 +0.106% → 可交易 −0.255R），
  而 RS020 +0.85%、RS021 score≥80 +4.49% 等"成立"结论全建立在无成本口径上。
- 【动作】
  1. 建立**双口径强制报告**：任何"正向成立"必须同时给出 ①无成本（选品质量诊断口径）
     ②DEC003+1tick（可交易口径）两列，且**只有可交易口径 >0 才能判"成立/立项"**。
  2. 对 RS020 臂2/3、RS021 score≥80 做带成本复算（DEC003 佣金 + 1tick 滑点），复算
     通过前，两者降级为"未证实方向"。
  3. 把 DEC003 成本函数抽成 `cost.py` 单一实现（复用 risk_budget.py 的佣金形态），
     禁止各脚本各自发明成本。
- 【成本】0.5 人日抽函数 + 2 人日复算。
- 【优先级】P0。

### 1.3 🟠 OOS 单一化（2022+ 已被反复消费）
- 【依据】2022+ 窗口被 RS012→RS013→RS019→RS020→RS021 反复回看，已退化为"第二训练集"；
  RS020 臂2 in −0.12% 反而 out +0.85%（regime 依赖）仍判"成立"。
- 【动作】
  1. 设**三块数据**：训练 2015–2021 / 验证 2022–2023（调参用，一次）/ **测试 2024–2026
     （只测一次，锁定）**。测试块只在最终结论时动一次，之后冻结。
  2. 所有"成立"结论必须给出 in/out/test 三列，且要求 test 不劣于 out 才算数。
  3. 对 regime 依赖型结论（RS020 臂2），必须报告"分 regime 的样本量 + 置信区间"，
     不允许"OOS 整体正但 in 负"被当作稳健信号。
- 【成本】0.5 人日立规，复算随各立项进行。
- 【优先级】P1。

### 1.4 🟠 多重比较与显著性纪律
- 【依据】9 信号基线无多重比较校正；IC 检验用 Pearson 但无显著性/样本量/时段稳定性声明
  （RS013 §4 自认"重叠采样 t 显著度虚高"）。
- 【动作】
  1. 引入 **Deflated Sharpe Ratio / Bonferroni-Holm** 到任何"从 N 个候选里挑出最优"的结论；
  2. IC 报告强制附：样本量、Pearson/Spearman 双口径、分时段（in/out/test）稳定性、
     去重叠采样（间隔 ≥ horizon）；
  3. "因子挖掘冻结令"（RS013 §6，做得对）从临时纪律升格为**常态机制**：任何新因子/
     条件/参数扫描必须预注册 + 一次性跑完 + 报告多重比较校正后 p 值。
- 【成本】0.5 人日（脚手架函数）。
- 【优先级】P1。

### 1.5 🟠 小样本与重尾纪律
- 【依据】n=133/+0.215、n=88/+0.364、n=45/trend_score 被当结论；RS021 score≥80 +4.73%
  由 FB(n=4,+406%) 重尾驱动，且数字三处打架（+4.49%/+4.73%）。
- 【动作】
  1. 小样本（n<200）结论一律附 **Bootstrap 置信区间**，并报告"剔除最重 1% 事件后是否
     存活"（重尾敏感性）；
  2. score 分桶类结论必须做**分品种去重尾 + 分年一致性**，单个品种/单年贡献 >30% 就
     标注"集中度风险"；
  3. 所有均值类结论同时给中位数（RS021 deep_dive 已有此意识，制度化）。
- 【成本】0.5 人日脚手架 + 随项执行。
- 【优先级】P1。

### 1.6 ✅ 保留并强化的好纪律（不要改坏）
- 预注册 + 机械判读（RS016 范式）、负结果如实入档、反同义反复（RS014）、自查前视
  （RS020 勘误）、换月复权自纠（RS017/DEC006）——这些是行业规范级资产，**新方法论
  只增不减**。

## 4. 策略模板和框架建议

### 4.1 🔴 context_tag 阶段判定地基重构（全框架最大软肋）
- 【依据】RS012 实测引擎 RANGE 精确率 39.8%、reversal 15.7%，GT 真值阶段中位持续仅 4–8
  根（≈1 个交易日）高频闪烁；RS019 证明方向判定劣于朴素 SMA20。整张"阶段→信号矩阵"
  建在不稳分类器上。
- 【动作】（与 §5 AI 策略联动）
  1. **短期**：给 context_tag 加迟滞（连续 2–3 次一致才翻转，RS012 §4a 已设计）；
  2. **中期**：把阶段判定从"规则链（摆动点+EMA 斜率+HH/HL）"升级为**轻量 ML 分类器**

  最关键的 key_levels（支撑/压力值）与 signal_categories/context_tag/valid_bars → 两套
  实现算出完全不同支撑位也会报"aligned"；legacy PoolEngine+SignalKMonitor 与 selection_runner
  +引擎双路径并存，双报警/双口径隐患。
- 【动作】
  1. DIFF_FIELDS 补 `support/resistance/swing_points/signal_categories/valid_bars`；
  2. 对"状态 vs 事件"漂移做显式对齐（否则影子通过 ≠ 模型等价）；
  3. 排期 legacy 路径退役（Phase D），收敛到单一路径。
- 【成本】0.5 人日（字段）+ 退役排期。
- 【优先级】P1。

### 4.7 ✅ 框架骨架不动（避免过度工程化）
- 【依据】子代理 D 定性"工程成熟、量化空心"——骨架对、工程已到位，瓶颈在选品 alpha。
- 【动作】**不要**再叠加新的工程组件（通道熔断、ack 队列、程序化移仓等）到选品 alpha
  未解决之前；把资源从"工程加固"转向"选品判据重构 + 契约落地"。
- 【成本】0（约束性建议）。
- 【优先级】P1（资源再平衡）。

## 5. 基于 AI 新型的策略研究建议（AI 新型策略）

> **核心定位（与项目哲学对齐）**：AI 的职责是**"判据/特征/关键位/信号组合的生成与
> 评分器"**，不是"黑箱下单器"。落地仍走完整治理链：**AI 生成 → 预注册验收（含前视/
> 过拟合护栏）→ HO 移交 → 影子 → 观察期 → 用户批准**。这与"不代客下单、结合人的
> 入场能力、先证后做"完全一致——AI 提升的是"给用户看的信号质量"，不是"替用户下单"。

### 5.1 🔴 首选方向：阶段判定 ML 化（直接补最软肋）
- 【依据】规则版 context_tag RANGE 39.8%/reversal 15.7%，且 RS019 证方向判定劣于 SMA20。
  这是全框架地基，规则链已到天花板，ML 分类器是最自然的补强。
- 【方案】
  1. **监督学习**：标签=GT（as_of 之后 realized），特征=严格 as_of 可得（动量 mom6、ER、
     ATR 归一化价格位置、量能 rvol_adj、摆动点结构、多周期一致性等，全部可算且无前视）；
  2. **训练纪律**：滚动窗口 Walk-forward + Purged K-Fold（embargo 一个 horizon 防标签泄漏）；
  3. **评估**：精确率/召回率 vs 规则版 对照（要求显著优于 39.8%），+ 切换频率下降验证；
  4. **落地**：作为 `context_tagger` 的 v2 实现，走 HO004 同款"交付→验收→影子→观察"。
- 【成本】1–2 人日原型（本地 6 主连 + 91 品种 5m/日线数据充足）。
- 【优先级】P0（与 4.1 联动）。

### 5.2 🔴 关键位/边界质量评分器（验证"选品层新口径"）
- 【依据】TEMPLATE §2.4a 把选品层价值重构为"给正确边界+方向"，但该口径从未验证
  （RS019 §3：支撑/压力回踩 n=6 不可判定）。
- 【方案】
  1. 用 ML 给每个关键位（prior_high/low、range 边界、gap_edge、密集区）打"被有效支撑/
     压力的概率"分——标签=未来 N 根是否在 ±tol 内守住（as_of 之后），特征=位的历史被
     触及次数、成交密度、距现价距离、波动率、量能；
  2. 产出"关键位可信度评分"进任务单，让择时层/用户知道哪个位更可靠；
  3. 预注册验收：高分位组的"支撑守住率"显著 > 低分位组。
- 【成本】1–2 人日。
- 【优先级】P0/P1。

### 5.3 🟠 因子/判据的自动化挖掘（受控版）
- 【依据】手工 Alpha101 移植信息量有限（RS013 判读①"经典 Alpha101 直接移植信息量有限"）；
  手工挖掘已触发冻结令。
- 【方案】
  1. 用**符号回归 / 特征库搜索**在严格前视护栏下生成新因子（Purged CV + Deflated Sharpe
     控制多重比较）；
  2. 每个 AI 生成因子走 MLIB 登记 + 预注册验收（同 RS013/RS016 标准）；
  3. 明确 AI 因子与手工 PA 判据的关系：AI 因子优先做**选品层排序/背景**，PA 判据维持
     择时层不变（符合"择时信号按 PA 设计、选品可补充精简"的架构定调）。
- 【成本】2–3 人日首版框架。
- 【优先级】P2。

### 5.4 🟠 信号组合/编排的学习型权重（S-004 的 ML 版）
- 【依据】S-004 冲突裁决当前是规则版（突破优先/回调降权，54.1% 正确率）；多重信号
  编排存在学习空间。
- 【方案】把"同窗多信号 → 最优入场方向"建模为**小样本分类问题**（特征=各信号 rank/
  方向/形态/阶段），用带正则的模型输出权重；但**不得替代规则，只做降权/排序增强**，
  规则版保留为兜底（可解释、可审计）。
- 【成本】1–2 人日。
- 【优先级】P2。

### 5.5 🟠 择时信号的二次过滤（detector 产出的 ML 增强）
- 【依据】择时层信号质量受阈值随意 + 选品层负拖累；detector 阈值从未校准。
- 【方案】对 detector 产出的 armed/triggered 信号，用 ML 做"触发后 N 根是否按预期走"
  的命中概率评分（标签=触发后 realized，特征=信号类型/形态质量/阶段/量能/波动率），
  低分信号降权或过滤——**在通知层增强，不改交易行为**。
- 【成本】1–2 人日。
- 【优先级】P2。

### 5.6 🟠 换月/事件的无监督异常检测
- 【依据】换月、跳空、异常波动是反复出现的框架缺口（换月接力、gap 链路）。
- 【方案】无监督（聚类/离群检测）识别换月边界、异常 bar、操纵性扫损，作为**前置护栏**
  喂给选品层和通知层（如"疑似换月→抑制旧合约信号"已有 HO005，ML 版做兜底增强）。
- 【成本】1 人日。
- 【优先级】P2。

### 5.7 AI 策略研究的治理红线（必须同步建立，否则 AI 是过拟合放大器）
1. **前视护栏是硬约束**：任何 ML 训练必须 Purged CV + embargo，标签只用 as_of 之后，
   特征只用 as_of 之前；违反即作废（对标 RS013 mom6 的教训）。
2. **可解释性底线**：不代客下单，所以 AI 给出的每个信号/评分必须附**可审计依据**
   （特征重要性 / 规则可解释版对照），黑箱不可进生产。
3. **防过拟合**：AI 模型复杂度受限（优先线性/浅树/带强正则），Walk-forward 全程，
   test 块只测一次；Deflated Sharpe 门槛。
4. **不越权**：AI 只产出"信号/评分/判据"，**永远不产出下单指令**；程序化下单维持冻结。
5. **走完整链**：AI 产物 = 候选，必须过 MLIB 登记 + 预注册验收 + HO + 影子 + 观察期 +
   用户批准，与手工产物同等待遇，**不因"AI"享受免检**。

### 5.8 AI 方向优先级排序（成本-收益）
| 排序 | 方向 | 理由 | 优先级 |
|---|---|---|---|
| 1 | 阶段判定 ML 化 | 直接补全框架最大软肋，数据现成 | P0 |
| 2 | 关键位质量评分 | 验证"选品层新口径"，闭环选品价值主张 | P0/P1 |
| 3 | 择时信号二次过滤 | 提升通知质量，零交易风险 | P2 |
| 4 | 信号组合学习型权重 | S-004 增强，规则版兜底 | P2 |
| 5 | 因子自动化挖掘 | 长期议程，先建护栏 | P2 |
| 6 | 换月/事件异常检测 | 护栏增强 | P2 |
